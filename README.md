CS110 WEEK 5 PROJECT DASHBOARD
PROJECT GUIDE — WHERE TO FIND EVERYTHING

This guide explains what each file does and exactly where to look when you want to open the website, change the design, edit the dashboard, or work on the 3D sphere.

==================================================

OPEN THE WEBSITE

First, download the project ZIP and extract it.

Open the extracted project folder. You should see index.html, styles.css, script.js, README.md, export-assets.js, and a folder named week4.

To open the dashboard, double-click index.html.

Keep all the files and folders together in the same folder. Do not move the week4 folder somewhere else. The 3D scene depends on files inside that folder.

If the 3D view does not load when you open index.html directly, try opening the project through a local development server. Some browsers restrict pages opened directly from your computer from loading other local files.


==================================================

START HERE — THE MAIN WEBSITE FILES

index.html
LOCATION: The main project folder.

This is the main page of the dashboard. It contains the dashboard sections, headings, labels, text, buttons, and the layout of the page.

Open this file if you want to change the words on the page, rename a section, or change the order of the dashboard content.

The page sections include the Week 1–4 review, the Week 5 app planning and development work, the Week 4 3D scene area, the R4 testing and revision section, and the R5 final submission section.

styles.css
LOCATION: The main project folder.

This file controls the dashboard's appearance. It contains the colors, fonts, spacing, page layout, cards, buttons, responsive behavior, and visual styling.

Open this file if you want to change the dashboard's colors, make text larger or smaller, adjust spacing, or change how the page looks on different screen sizes.

script.js
LOCATION: The main project folder.

This file controls the dashboard's interactive features.

Open this file to work on form behavior, saving answers, loading saved answers, checklist behavior, importing answers, exporting answers, and the full-website export process.

If a dashboard button does not respond or saved answers are not working, this is one of the first files to inspect.

README.md
LOCATION: The main project folder.

This is the project instruction guide. It explains how to open the website and where to find the code.

export-assets.js
LOCATION: The main project folder.

This file contains the files used by the offline full-website exporter. It helps the dashboard create a ZIP containing the website and saved entries.

This is a generated support file. You usually do not need to edit it by hand. If you change the website files and need the exporter to include those changes, the export asset data may need to be regenerated.


==================================================

THE 3D SPHERE — EXACT FILE LOCATIONS

Open the folder named week4 in the main project folder.

Inside week4, these are the important files:

week4/3d.html
This is the HTML page for the 3D scene. Open this file to inspect the page structure for the 3D view.

week4/js/app.js
This is the main JavaScript file for the 3D scene. It controls the scene setup and the 3D behavior, including the sphere and its interactions.

If you want to change how the sphere is created, how the scene works, or how the explosion and reassembly behavior functions, start by looking in this file.

week4/css/styles.css
This file controls the appearance of the 3D scene page, including its layout and styling.

week4/vendor/babylon.js
This is the Babylon.js library used to display the 3D scene. It is a large third-party library. Do not edit this file.

week4/vendor/license.md
This file contains license information for the included Babylon.js library.

week4/vendor/NOTICE.md
This file contains a notice related to the included library.

week4/TestNotes.txt
This file contains notes from the original Week 4 starter project.

IMPORTANT: Keep the entire week4 folder together. Do not rename or remove its subfolders, especially js, css, and vendor. The 3D page relies on those files being in their expected locations.


==================================================

WHERE TO GO FOR COMMON CHANGES

To change the wording, headings, or section content on the dashboard, open index.html in the main project folder.

To change the dashboard colors, fonts, spacing, or overall design, open styles.css in the main project folder.

To change dashboard buttons, autosaving, importing, or exporting, open script.js in the main project folder.

To change the sphere, its movement, explosion, or reassembly behavior, open week4/js/app.js.

To change the layout or styling of the 3D view, open week4/css/styles.css.

To inspect the HTML structure of the 3D view, open week4/3d.html.

Do not edit week4/vendor/babylon.js. It is the 3D engine library, not the project's own scene code.


==================================================

THE DASHBOARD SECTIONS

The Week 1–4 section is for reviewing the ideas and skills covered in the earlier weeks.

The 5A and 5B sections are for planning and developing the themed app. Use the input areas to record the app's purpose, design, and development work.

The Week 4 scene area contains the 3D view from the starter project.

The R4 section is for testing the app, recording issues, and explaining revisions.

The R5 section is for checking the final submission requirements and organizing the final project.

Use the input fields and checklists to keep your work organized as you complete the project.


==================================================

SAVING YOUR WORK

The dashboard automatically saves form entries in the browser's local storage.

This means entries are saved in the browser and on the computer where you entered them. They are not automatically saved to GitHub or Canvas.

Export answers (JSON) creates a separate JSON backup of your answers.

Import saved answers loads answers from a JSON backup you previously exported.

Export full website + entries creates a ZIP containing the website and the current answers. Extract that ZIP into a new folder before opening the exported index.html.

Keep a separate JSON backup of important answers in case you need to move to another browser or computer.


==================================================

IF THE 3D VIEW DOES NOT WORK

Make sure you extracted the entire project ZIP.

Make sure the week4 folder is in the same main folder as index.html.

Make sure week4/3d.html, week4/js/app.js, week4/css/styles.css, and week4/vendor/babylon.js are present.

Do not open or move only the 3d.html file by itself. Keep the full project folder structure intact.

If the scene still does not start, open the browser developer console and check for error messages. A local development server may be needed if the browser blocks local file access.
